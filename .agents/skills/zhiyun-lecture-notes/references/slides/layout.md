# Slides · layout — 居中图片与有意义的组图

仅在启用嵌图时使用本模块。选择版式前，先按 reading 模块完成内容审阅。

## 位置与成组

每张图放在解释或使用它的具体文字**上方**。锚点是相关解释，而不是最近的标题：标题后可能先有引入段落、定义或前面的步骤，之后才需要这张图。写作时同时确定段落边界和锚点。不要把所有图片提到小节开头，不要为每张图造一个标题，不要给每段随意配图，也不要在出图前把图中的整个操作讲完（一句引入可以）。

一个合理但不强制的局部顺序：标题 → 可选的引入 → 图或组图 + 简短图注 → 对应解释 → 下一张图或组图 + 解释。共用的来源折叠可以放在整个局部图文对之前或之后，但无关文字、另一个主题或来源控制块不能隔断图与解释（图注和简短的观察提示属于这一对）。像素上相邻本身不等于语义对应。长序列应穿插小而连贯的图片/步骤组，不要把所有图片堆在好几屏文字上方。在 Complete 中，常显教程和每个细节折叠内部同样遵守这种局部性；折叠例子的图跟着该例子，不放在章标题处。

- 单图：居中；关键内容仍清晰时，可占阅读栏的全宽、一半或三分之一。
- 两图：真正的对比、前后状态，或同一任务的两个连续步骤。
- 三图：三个并列情形或连续步骤，仅当每幅在该尺寸下都清晰可读。
- 四图：2×2 矩阵，按左上 → 右上 → 左下 → 右下阅读；为每个情形或步骤加标签。
- 无关主题、对象或比例不一致、内容密集的页面分属不同单元；相邻（例如历史照片挨着技术定义）不构成有用的组合。不要机械地把每两、三、四个相邻文件成组；单图同样有效。只有实际 PPT 缺少某种必要表示时才添加 ASCII 图，不作为第三份副本。

图注一到两行，说明图中是什么；计算、结果或论证写在相邻正文里。分图使用描述性图注，例如“1. 初始状态”“2. 第一次操作”“3. 完成后”，并用这些标签解释变化。不要只凭文件名推断图注。不要为了凑网格丢掉必要的中间帧；较长的序列按原顺序拆成几组局部连贯的组图。

## 清晰度优先于紧凑

宽度指**内容栏**，不是屏幕。符号清晰的稀疏图可用 50% 或约 33%；密集表格、代码、小字号公式和复杂图形需要全宽或依次单图。处处全宽和过小的分图都不是目标；拿不准时用更大的版式，并标注视觉质量未核验。保留宽高比、原始分辨率、条件、图例和坐标轴。不要变形、悄悄裁剪或重绘幻灯片；只有任务允许时才裁剪，并保留原图和明确的裁剪出处。小屏幕上组图纵向堆叠、紧凑图加宽；可以缩放不代表默认文字可以看不清。打印时优先清晰度和原始顺序。

## 支持的 Markdown 内嵌 HTML 语法

借用 LaTeX figure/subfigure 的居中效果，不借用它的浮动定位。Handouter 离线 HTML 只提供以下固定类；不要自造内联样式、脚本、外部样式表或图片变换。单个 `ppt-figure` 可加 `ppt-full`、`ppt-half` 或 `ppt-third`；不加时容器为全宽，图片保持自然尺寸上限和宽高比。两、三、四图分别用 `ppt-grid ppt-cols-2`、`ppt-grid ppt-cols-3` 或 `ppt-grid ppt-grid-2x2`，内含相应数量的 `ppt-figure` 子元素；组图分栏**内部**的图不再加 half/third 宽度。保留各自独立的图片资源，不要拼成低分辨率的缩略总图；排版不需要 Markdown 表格。

每个完整 HTML 块前后留空行，解释、Markdown 列表、代码和数学放在块**外面**。图注用纯文本或简单安全的 HTML，不用 Markdown 或数学。需要符号时写成可读的纯文本记号，如 O(log n)、2^r − 1、B_k、≥，不要展开成“2 的 r 次方减 1”“k 选 d”这类文字。图注描述的对象必须是这张图实际显示的内容：动画拆页的中间帧只显示部分内容时，按实际可见部分写，不按整页最终内容或所在章节的主题写。转义字面的 &、尖括号和属性引号。使用真实的相对图片路径和正斜杠；加引号的 src 值可以含空格。

以下仅示范语法，不是课程事实（每个路径和图注都要换成已审阅的材料）：在**一个**标题下，先是正文之后的一张图，再是一组两图，各自带解释。

```markdown
### 本教学单元的一个问题

引入问题，但先不解释图中的操作。

<figure class="ppt-figure ppt-half">
  <img src="../slides/images/actual-state-a.png" alt="已核对的第一个状态">
  <figcaption>第一个状态或情形。</figcaption>
</figure>

解释这个状态、所做的操作及其原因。引入下一阶段。

<div class="ppt-grid ppt-cols-2">
  <figure class="ppt-figure">
    <img src="../slides/images/actual-step-1.png" alt="已核对的初始状态">
    <figcaption>1. 初始状态</figcaption>
  </figure>
  <figure class="ppt-figure">
    <img src="../slides/images/actual-step-2.png" alt="已核对的下一状态">
    <figcaption>2. 操作后的状态</figcaption>
  </figure>
</div>

在这里用这些分图标签解释从 1 到 2 的变化。
```

这些类是 Handouter 离线 HTML 的约定，不是标准 Markdown；不要声称所有阅读器渲染效果相同。本地 Typora 阅读副本由应用另行导出；保持规范语法，不为它注入 CSS 或脚本。只有无法提取真实图片的本地网页 Agent 交接，才可以在同一位置留下固定待补标记 `[插图位置：Slides.pdf 第 N 页]`（这是由 Host 检测的标记，不是对文件名的声明），并写明分图顺序、关系和预期尺寸，同时报告待补图。已提供图片时（如云端任务）不得留下此标记，Host 会拒收。不得虚构可用的图片链接。

## 阅读检查

检查实际的组图输出、紧凑宽度、小屏幕和关闭的 details 内的图：数量、顺序、图注、对应解释、清晰度，以及其后数学和列表的渲染。每张图都离线可用，不依赖可丢弃的缓存。Prompt 规则或通过的结构测试都不能证明语义匹配或幻灯片实际可读。
