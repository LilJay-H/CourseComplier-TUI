# 中文样例的来源与使用方法

本目录的样例全部是手工编写的合成材料：课程、讲者、对象、数字、原话和行号均为虚构，不对应任何真实课程，不是模型验收结果，也不是当前任务的证据。只学习编辑方式；不把样例的事实、数字、行号、图号或小标题迁移到任何任务。样板只展示相关单元，正式交付的外壳顺序仍按 common/presentation。

## A：合成课堂转写（技术推导类）

虚构主题：日志为什么要“攒一批再落盘”。身份：合成 ASR，未经回听，没有时间索引；行号只属于本样例。转写刻意保留识别错误（“皮亮”应为“批量”，“落盆”应为“落盘”）、一次自我更正和末尾的不确定通知。

```text
L1 好我们接着上次讲那个日志啊，每来一条记录我们就要把它写到盘上去对吧，这个叫落盆，落盘。
L2 那落一次盘呢大概要等五毫秒，你一秒钟来一千条，每条都单独落，那盘根本忙不过来对吧？
L3 所以呢一个很自然的想法就是皮亮，就是我攒一批，攒够了一起落。
L4 攒K条一起落的话，那落盘次数就变成原来的K分之一，对吧，吞吐就上去了。
L5 有同学问，那攒的时候断电了怎么办？问得好啊，攒在内存里还没落的那一批，断电就没了。
L6 所以K不是越大越好，K越大，最早来的那条等得越久，断电丢的也越多。
L7 那最早那条要等多久呢，它要等后面的人都到齐，所以最坏要等K个间隔，再加一次落盘。
L8 哦不对，我刚才说成K了，是K减一，K减一个间隔，大家改一下。
L9 实际系统里一般是两个条件哪个先到就落，要么攒够K条，要么等够一个时间上限T。
L10 这个原理今天就讲到这，下周呢可能会叫人上来讲一下这个两个条件的落盘，讲得好的平时分加一点。
L11 还有啊，下周可能会有一个小测，大家带好纸笔。
```

单元划分：A1（L1–L4）逐条落盘的瓶颈 → 批量；A2（L5–L9）批量的代价、学生提问、K→K−1 的更正、双条件触发；A3（L10–L11）行动信息，两处都是“可能”，并要求带纸笔。源内没有给出“K 至少取多少”，也没有给出 T 的取值；样例中的这类计算一律标为编辑核验。

## B：合成课堂转写（观点与论证类）

虚构主题：地方志能否当史料用。身份同 A。转写没有说话人标签，L5–L6 是学生小组发言，依据是 L4 的点名与“我们组”的自称；L7 回到教师点评。

```text
L1 我们今天说地方志，地方志能不能当史料用？能用，但是要知道它是谁编的、为谁编的。
L2 一般是地方官主持修的，那它写本地的好事多，写坏事少，这个是它的立场。
L3 所以用的时候呢要跟别的材料对一下，比如说账册啊碑刻啊。
L4 下面请第三组同学讲一下他们找的那部县志。
L5 我们组看的是一部清代的县志，它记那一年的水灾只写了民无大损，但是同一年的一块碑上记了很多人家迁走了。
L6 所以我们觉得这部县志在这件事上可能是报喜不报忧。
L7 嗯，这个对比做得挺好，但是报喜不报忧这个结论要小心，碑上说迁走，也可能有别的原因，你们再找一找别的材料。
```

单元划分：B1（L1–L3）教师给出的使用方法；B2（L4–L7）学生的对比与暂定判断，以及教师对结论强度的保留。
