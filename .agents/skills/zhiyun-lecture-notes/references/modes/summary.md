# Mode · summary — 速览讲义

Summary 让没上这节课或需要快速回顾的人，用最短时间知道：这节课讲了什么、哪些是重点、要做什么。它不是把 Full 压短，而是重新选择和组织：每个保留的内容都要讲到能看懂。

## 结构

1. 按 common/presentation 的外壳：行动框 → 折叠课程信息。
2. `## 本讲速览`：3–7 条短列表，每条一句话，说明本讲要解决的问题和主要结论；条数随内容，不凑数，也不在这里展开讲解。
3. 按教学单元讲解，每个单元用一个 `###` 小标题，一般沿讲课顺序；课堂内容来回跳跃时，可以把同一主题合并成一个单元。每个单元写：
   - 核心概念、定义、公式或结论，以及它成立的条件；
   - 一个最能说明问题的例子，写出关键步骤和结果；
   - 必要的易错点或辨析（讲者纠正过的误区优先）。
4. `## 易混与提醒`：材料里出现讲者纠正的误区、易混概念或明确提醒时必须写；只放材料里确实有的，不重复前文。确实没有时省略。
5. 每个主章一个关闭的来源折叠；结尾一个关闭的待核对折叠（有疑点时）。

## 重点怎么判定

重点必须有依据：讲者明确强调（“这个要记住”“经常会考”“很重要”）、反复回到同一点、课件把它列为要点/小结/例题、或与作业和考核直接相关。有依据的重点要在对应位置写出依据，如“讲者强调”“课件小结列出”“与作业相关”，不凭模型自己的判断加“必考”“核心考点”之类标签；没有依据的内容照常讲，不冠以重点。

## 取舍

- 可以省略：旁支故事、课堂互动过程、个人经历、题外话、同一内容的第二个相似例子。
- 不能丢：影响结论的前提、条件、例外、否定、单位与分母、讲者的明确更正，以及全部行动信息。省略细节不能改变结论的确定性：“可能”不能写成“会”，讲者观点不能写成客观结论。
- 不同来源的同一组数字归属不一致时保留冲突，不为简短只留一个。
- 不添加材料外的背景、例题、考点或结论。

## 图

允许读 PPT 和嵌图时，选核心图：关键结构图、例题页、对比表或课件小结页，一般每个单元一两张，紧贴对应说明，位置与语法按 slides/layout。纯文字页可转成文字，不必截图；不为凑图而插图，也不因为是速览就默认不用图。

## 篇幅与语言

目标是 5–10 分钟读完主要内容；这是产品目标，不是字数或覆盖率指标，不能用篇幅证明完整。用短段落和必要的列表、表格，公式按 common/presentation。不要装饰性的 Mermaid/ASCII 图或冗长时间线。

## 与其他模式的关系

可以复用已核对的 Full/Deep 文字和事实，但必须回到来源核对前提、更正和行动，不能只以另一份草稿为依据。Summary 是唯一允许按主题合并课堂顺序的模式；合并后仍要让读者看出各结论来自哪个教学单元。
