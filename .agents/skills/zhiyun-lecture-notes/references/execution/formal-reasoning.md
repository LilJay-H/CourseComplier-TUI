# Execution · formal-reasoning — 数学、算法与代码

本条件模块依据当前材料中的文本信号选择，而不是依据课程标题。信号只是路由提示。只对实际的形式化内容做以下检查；不要在叙述性讲课中编造数学，也不要把成绩占比当成定理。公式只出现在已查看的幻灯片中时，同样对其做这些检查，并报告文本路由的局限。

把公式或过程作为知识呈现之前：

1. 写明其约定：符号与定义域、初始状态、序列起点、单位、代价模型、高度还是深度、子树还是整体结构。用前几个合法的基础情形检验递推式和闭式。约定改变时重新核对下标；不要死记一条通用的下标平移。
2. 区分等式、近似、不等式和渐近阶。极限系数不是有限规模下的百分比界；最小规模的递推不是每个实例的实际规模。推出严格的界需要每一步都是有效的不等式。
3. 按例子给定的构造方式和操作顺序复现例子。需要时检查空输入、查找失败、分支和镜像情形。某个边界未讲时，把对它的解释标为补充，而不是恢复出的教师内容。
4. 用小例子或反例检验全称说法。区分逐节点的结论与总体变化、单次操作与操作序列、摊还与概率平均、抽象基本操作计数与物理运行时间。
5. 在所有模式（包括 summary）中保留初始化和前提。教师的直觉仍是直觉；编者举例的验证要标明。把一段称为证明需要每一步都有效，而不只是终点正确。
6. 这些检查同样适用于折叠中的例子、图注和标题：正确的递推式必须与每个数值例子一致，标明为证明的内容需要有依据的不等式，不能把近似升级为等式。按所述的构造或插入顺序推演，不要假定为幻灯片上的最终状态。修正主段落不会自动修正折叠里过时的答案。
7. 来源中的记号错误或不清楚时，在证据层保留可追溯的原文。逐字引语保持不变；编者更正放在引语之外。full/deep/summary 不得悄悄把可证明错误的公式当作正确内容呈现。给出带标注、自洽并写明假设的更正，或保留有依据的定性说法并加一个聚焦的待核对标记。不要把编者的计算写成教师对话、明确的考试要求或课堂例题。
8. 保持代价模型一致：一次抽象操作不一定等于一次实现层面的基本操作。新的记账类比必须为每个被计费的操作付费，写明初始状态和任何额外费用，并保持编者身份。即使另有标明的核验使用不同模型，引语中仍保留来源的原始计数。
9. 对照分母和方向检查每个百分比与比值：耗时减少的百分比不等于速度提升的百分比；描述比值的文字必须与所示公式的分子和分母一致。对数内的量是相对于明确参照的无量纲比值。
10. 充分条件并不自动是必要条件。对“A 是 B 的必要/充分条件”，在内部检查中分别写出两个蕴含（充分性：A 推出 B；必要性：B 推出 A），并在所述范围内为每个声称的方向寻找反例；单向证明不能作为反向的证据。用反例和模型的适用范围检验“当且仅当”“总是”“从不”和“物理极限”：只差概率为零的部分的相等不是集合相等；测量结果保留其所述条件（如设备、年代和负载），不变成普遍极限。来源混淆了这些时，保留其证据身份并标注更正；不要悄悄把来源改成一条正确的引语。
11. 算例要以结果、单位和合理性检查收尾；有意留给读者的计算标为练习。教师布置的证明或省略的步骤仍是行动项；编者的解答即使正确也要单独标明。只给出部分动机的定理不能称为已完整建立的证明。

内部核验不等于可以添加未讲过的教材证明。只有对本段有帮助时，才展示新的检查或推导，标明编者身份，并遵守外部来源许可。
