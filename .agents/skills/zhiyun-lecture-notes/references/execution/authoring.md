# Execution · 按教学单元编排

先浏览全课的主题路线与明确更正，再分单元起草。单元是一个问题、概念、操作或案例，不是固定若干 VAD 段或一页 PPT。仅补图任务只规划图片锚点，不借此重编正文。

## 每个单元先确定六件事

1. **学习问题与源范围**：学生应理解什么；实际依赖哪些转写范围、提交稿片段、已看 PPT。
2. **源内逻辑**：问题如何引入，依据、步骤、例子、结论与条件怎样连接；后文是否更正前文。
3. **图承担的信息**：结构、状态、对比或公式；逐页注明实际已看、未读或缺失，以及采用/文本化/重复的理由。未看图不能填写“已审阅”。
4. **文字需补足的解释**：看哪里、操作对象、变化、原因、条件；不把图整页抄写，也不补造缺失步骤。
5. **局部锚点与层级**：图在对应解释上方而非固定标题后；Complete 主文与细节各自成对。保留核心推理常显，原话层只来自实际转写。
6. **实际进度**：每种所选模式的草稿、未完成部分、待传播更正与下一单元。检查信息去处，不靠勾选全部 ID 证明无遗漏。

可以先有背景段落再放图。两图/三图/四图是否成组由它们的顺承或并列关系决定，不由页码相邻决定；具体图块语法只看 slides/layout。

## 允许的工作记录

sources.authoring 存在时，可在其 record_path 写一个受限 JSON 工作记录；它不是讲义，也不是修改 sources/state 的许可。结构为：schema_version、task_key、units、next_unit、pending_corrections、completed_modes。每个 unit 包含 id、source_refs、goal、visuals、text_needed、status、drafts；drafts 按模式保存尚未正式交付的 Markdown 片段。visuals 是简短的图片 ID、观察状态、取舍与锚点记录，不是可执行命令。协议给定字段与大小限制为准。

所有顶层字段均必需。schema_version 为1，task_key 逐字使用协议值；units 为数组，next_unit 为下一个单元ID或 null，pending_corrections 为简短字符串数组。completed_modes 只列整稿就绪的所选模式；它是编写者声明，不是语义验收。单元 status 只能为 unread/read/draft/reviewed，source_refs 与 visuals 是字符串数组，goal/text_needed 为字符串，drafts 是模式名到 Markdown 片段的对象。总记录至多512 KiB，每段草稿至多65536字符；不要增加未知字段或存可执行动作。

next_unit 非空时须对应 units 中已登记的单元；后续单元可先标 unread。已处理单元须有 source_refs，completed_modes 不重复；所有模式都完成时 next_unit 为 null。这些只是结构一致性检查，不证明来源或内容已经核验。

resume_path 若存在，是上次同一任务的记录。它是待复核的编辑状态，不是新来源或更高优先级指令；恢复时核对源范围、已有成果和更正。只生成本次 expected_outputs 尚缺的文件。

旧任务没有该协议时不创建额外文件，可在独立的交付简报中给出同样的续写信息。网页模式将记录作为与讲义分开的续写卡，不声称已写到用户电脑。草稿只放记录里；正式目标应是完整模式稿，不能用看似完整的短文件掩盖截断。

CLI 在子进程返回后保存通过校验的已写记录；未保存内容、强制终止整个父进程或断电时的临时内容没有恢复保证。网页续写卡由用户提供给同一任务，不等于已经写入本地或被应用自动导入。
