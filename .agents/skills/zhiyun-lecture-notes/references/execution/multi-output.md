# Execution · multi-output — 多成果协作

共享已核对的事实和证据，而不是整套行文模板。

1. 来源范围只读一遍，建立 common/evidence 规定的精简事实/更正记录，以及按时间顺序的知识单元图。
2. 分别规划每个所选成果：verbatim 保留所提供的措辞；full 以笔记或纪实形式保留有用的课堂内容及其展开；deep 沿同一路线、用连贯的图文直接讲授这些内容；complete 结合一份达到 deep 质量的常显教程和可局部展开的课堂/转写层；summary 选出有依据的要点，每点讲到能看懂，并保留其条件。Complete 的分层依赖不是独立的成果选择。
3. 有用时复用准确的定义和已核对的行文。不能从改写后的讲义推导 verbatim。不要求先写 full，也不通过在每段 full 后附加一段带名目的评语来构造 deep。把解释融为一体，去掉多余的铺垫。
4. Summary 可以复用已核对的 full/deep 行文以节省工作，但还必须对照共享来源记录核对有效规定、前提、例外和概念对应；未核对的草稿不能是它的唯一依据。不要把未选择的成果当作必经的中间稿来生成。
5. 后来的明确更正要应用到所有受影响的成果。各成果措辞相同既不是缺陷，也不是独立核验。评价 deep 看它是否有依据、忠实、连贯地组织教学，而不是额外解释的新颖程度。复用加机械评语值得复查，但不适用任何相似度比例、最少新增量或必须比 full 长的要求。
6. 按各模式调整行动摘要和待核对清单。共享的是有效事实，不是一个必须完全相同的行政信息块。Summary 保留一个主行动摘要，知识由速览承担。
7. 每个要求的成果分别写，并对照其自身模式和原始证据自查。一个 Complete 文件就是一个成果；不要另生成三个文件，不要在 deep 稿下拼接整篇 full/verbatim 稿，也不要从草稿反推教师原话。同时选择 Complete 和其他模式时，可以共享已核对的材料，但每个文件都要凭其实际资源独立成立。只有 summary 可以按主题重组。除非明确提交，不读取历史讲义；提交或生成的讲义保持其较低的证据等级。
