# Common · 阅读版式（唯一通用规范）

## 文档与顺序

标题 → 有依据时的常显行动框 → 折叠课程信息 → 正文 → 有疑点时的整体折叠待核对。

除 summary 外保持课堂宏观顺序、问题引入与论证依赖；相邻表达可以整理为自然段，deep 可在同一教学单元内组织小节。前置行动框是导航，不是重新排列课堂内容的许可。Complete 整份文件只有一套前置信息和结尾核对，展开层不重复它们。

## 行动信息：一次完整、始终可见

材料涉及作业、小测、考试、小组任务或考核时，用以下形式汇总有效规则及行动性未决问题；没有则省略，不声称课程没有考核。

```markdown
> [!IMPORTANT]
> **作业、测验与考核重点**
> - 填写本课实际行动，保留对象、条件、例外与暂定语气。
```

行动框只放有来源的作业、测验、考核、提交与课堂安排；知识速览按模式放在正文或 summary，不占用行动框。教学重点不能自行改称“必考／期末高频／考研必考”，只有讲者或课件这样说时才照写并保持原情态。

通读全课后才定稿，纳入末尾提醒与更正。课末宣布的作业与安排已在行动框完整列出时，正文不再单列一节重复，只在原位置补充行动框没有的内容。正文在原位置保留有增量的解释、问答或过程，不再整段复制重点框；summary 的速览侧重知识。不能为缩短而删影响行动的条件，也不把范例文字写进成品。用一个相邻关闭的“重点事项时间与来源”映射各项出处。

## 课程信息、来源与待核对

以下只演示语法，不是待填写后原样保留的模板：

```html
<details>
<summary>课程信息</summary>
<p>课程与材料身份填写已确认内容；日期、讲者未知则省略或明确未知。</p>
</details>
```

每个主章放一个关闭的“本章时间与来源”，或在文末用一个关闭的“各章时间与来源”按章列出行号/时间范围；不能只写整课的总范围。长章确有独立证据组时可用必要的“本节时间与来源”；不为每个自然段、图片、速览条目添加按钮。图文共用证据，来源框放在整个图文单元之前或之后，不能隔断图与对应解释。

```html
<details>
<summary>本章时间与来源</summary>
<p>时间与出处使用本任务实际信息；非连续来源分别列出，保留各信息点的对应。</p>
</details>
```

时间精度按 format 规则展示，原始精度留在映射内。未知原因如实区分缺失、未经核对与来源不可靠；PPT 展示时间不顶替发言时间。编辑补充没有课堂时间则标“不适用”，不编造时间。

```html
<details>
<summary>待核对</summary>
<p>仅写真实疑点、已有证据及需要确认的字段。完整清单和证据都在此折叠内。</p>
</details>
```

不要把事项常显在“## 待核对”下面，只折叠它们的来源。无疑点时省略。影响作业/考试或关键公式的未决点仍要在对应正文/行动框短提示；无意义噪声不变成学生待办。必要归属不等于给每句加“教师说/编者核对”。

## 文字、数学与图块

一个自然段发展一个微主题，不按 ASR/VAD 边界机械断段。小标题服务真实学习任务；过程才编号、平行比较才用表格，不把整篇写成清单。保持术语、符号与条件一致。

行内公式用 `$...$`；块级公式的起始 `$$`、公式内容、结束 `$$` 分别独占行，并与上下文合理分段，列表和引用内保持同级缩进。代码才用代码围栏。流程演变、状态迁移与架构流转优先用 Unicode 箭头 `→`，不滥用 `$\to$`。HTML 块前后留空行；所有折叠框（`<details>`，含 Complete 各层）的正文用 `<p>...</p>` 紧凑封装（换行用 `<br>`），`<summary>` 与正文之间及 `</details>` 之前不留裸空行，否则 HTML 块会被空行打断，`</details>` 外露在阅读面上。元数据转义 `< > &`。不要使用 `open`，不要把实际整页 HTML 放进代码围栏。成品只使用本文规定的折叠（重点事项来源、课程信息、章节来源、待核对）和模式规定的层；不添加“课件使用情况”“处理记录”“审核说明”之类的过程折叠，内部编辑记录不写进成品。

**数学输出契约**：Markdown 中的公式采用 LaTeX，不把复杂公式改成普通字母串；给 `<details>` 加 `open`、在 HTML 内换美元定界符或插入脚本都不是兼容修复。表格公式用 `\lvert...\rvert`、`\mid` 等明确命令，避免裸 `|` 被解释为分列；逐行检查列数与尾列内容。成品不得含控制字符：`\text`、`\times`、`\frac`、`\approx`、`\to` 等命令须完整保留（本地脚本写入用原始字符串或正确转义及 UTF-8，不对整段文本做通用反转义）。离线 HTML 的公式转换和本地 Typora 阅读副本由应用/Host 生成。

图文位置、居中宽度与组图语法仅以 slides/layout 为准（图紧邻对应说明，前面可有背景引入，不要求紧接标题）；Complete 的局部层级由 modes/complete 规定。

最终按实际阅读面检查：关闭后的按钮密度、连续段落、表格/公式/图片以及窄屏可读性。标签数量本身不是清爽或忠实度的证明。
