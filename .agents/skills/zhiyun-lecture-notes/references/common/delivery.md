# Common · 成品身份、命名与文件边界

讲义写作 Agent 负责生成指定内容，不负责替用户初始化应用、搬迁工作区或清理缓存。以下规则适用于全部模式，也适用于 Complete 的每一层。

## 输出路径以任务为准

- `expected_outputs` 是本次唯一的可写成品列表；只创建指定新文件，不擅自改名、另建桌面目录或覆盖旧文件。目录初始化、日期解析、唯一 ID、版本分配和文件发布由 Handouter 应用完成。
- 日期只能采用任务中有依据的授课日期或用户明确确认的日期；没有则省略或写“授课日期待确认”，不能用今天、生成/下载时间、文件修改时间代替。标题不露内部讲次 ID，但证据层保留实际来源身份。
- 目录设置、稳定 ID、日期与版本分配由应用负责；原始输入和历史成果只读。

## 成果、资料与中间产物分离

最终成果包括正文及必需图片/离线资源。唯一音频、转写、PPT 和恢复记录不是可删缓存；目录迁移与清理由应用处理，写作任务不执行。

- 不输出指向一次性 Agent 执行目录、临时解压目录、缓存、绝对本机路径的图片或展开链接。使用任务允许的稳定相对资源；离线 HTML 应嵌入资源。
- Complete 的详细层与清晰逐字层必须随正文保存，不能通过链接另读未交付的 full/verbatim、临时文件，也不能点开再调用模型。
- 不假称单独一个引用了外部图片的 Markdown 是自包含成品。尚未发布独立“成果/”资源包时，准确说明 Markdown 仍依赖随工作区保留的相对图片；单文件离线 HTML 必须实际导出后才可宣称可携带。
- 生成任务不执行“删除中间产物”。应用层清理必须针对可重建、非活跃、确切条目，先预览并获得确认；不因隐藏或 ignore 就默认安全可删。

## 渲染与交接

CLI Agent 只写指定 Markdown；HTML 由 Handouter 在请求该格式时校验并导出。网页/GUI 在用户要求且能力支持时可交同名 HTML；已经要求但能力不足时交完整 Markdown 并说明“HTML 待本地导出/补图”。未请求 HTML 时只交约定格式，不把缺少 HTML 写成导出失败，也不自行增加输出。HTML 与正文一致，真实图像内嵌、公式离线呈现，无 CDN/远程脚本；不以改扩展名、缺图或裸 LaTeX 冒充成品。

工作记录仅在 sources.authoring 显式授权时写到指定位置，不扩展成果列表；无该协议的旧任务不创建额外文件。网页续写记录与讲义分开保存。结束简报路径、实际范围、证据缺口与待导出状态，不把规则或结构测试当作真实语义验收。
