# 输出命名、首次目录设置与资料分层

状态：2026-09-17 已接入新任务的 CLI/TUI；旧工作区保持原路径，不自动迁移。验证范围以 PROJECT_STATUS 为准。

## 应用层目标

- 文件夹、manual ZIP、web 上传目录使用课程名称和真实授课日期；讲义再带模式和递增版本号，内部稳定讲次 ID 不变。Unicode 使用 NFC，清理 Windows 非法字符；同名/大小写/同日冲突加稳定 ID 摘要，不覆盖目录。
- 日期来自可靠回放元数据或用户确认。未知就标待确认，不用今天、下载时间、生成时间或文件修改时间代替。同课同日多讲次需消歧。
- 首次启动在同套 curses 主界面显示 DIRECTORIES，RUN 新任务前须确认并 SAVE；默认实际桌面的 Handouter/输入、Handouter/输出。Windows 使用 Known Folder，Linux 读取 XDG，macOS 使用用户 Desktop。配置保存在系统用户应用配置目录的 Handouter/directories.json；读取不创建目录，显式保存后应用创建所选根目录。配置保存全局默认输出目录、课程专用输出根目录、课程别名及课程文件夹命名策略；新任务解析优先级为显式 `--output-dir` > 课程专用目录 > 默认输出目录。旧 schema v1/v2 均继续读取，下一次保存升级到 v3。仍支持拖入任意目录文件。
- 课程别名用于身份匹配，不替换正式课程名。例如 `计组` 可映射到 `计算机组成`，`ADS` 可映射到 `高级数据结构`；课程专用输出、Folder Name 策略和后续运行都共享 canonical course。别名大小写、Unicode NFC 与连续空白按规范化值匹配，冲突到另一门正式课程或别名时拒绝保存。
- Folder Name 支持 `auto / always / never`。`auto` 为默认：当输出根目录最后一级已等于正式课程名或任一别名时，外层讲次目录只用 `MM-DD`；否则用 `课程-MM-DD`。`always` 永远带课程名，`never` 永远只保留 `MM-DD`。这只影响外层课程包目录，不改变内部正式课程名和带完整年份的成果文件前缀。
- 最终成果、资料与交接、可重建中间产物分开。唯一音频、转写、课件、任务快照和恢复记录属于需要保留的资料。

当前新任务布局：

```text
输出/课程名称-MM-DD/        # auto 且输出根已是课程名/别名时可直接为 MM-DD/
  .handouter-collection.json   # 稳定 ID、日期和目录身份，不含凭证
  成果/notes/                 # 可读 Markdown/HTML
  成果/slides/images/         # 实际引用的 PPT 图片（需要时存在）
  资料与交接/<稳定讲次ID>/     # 音频、转写、课件、Prompt/Skill、状态、已验证原稿历史
  中间产物_可清理/            # 成功阶段副本；未持久保存的材料不允许清理
```

## 实施和验收边界

CLI 新任务默认课程包布局；Python service API 为兼容已发布调用方仍默认旧协议，可传 organized=True、lecture_date；CLI --legacy-layout 仅保留旧脚本兼容。原有内部协议保存在“资料与交接”，Agent 的 expected_outputs 指向其中带课程名/日期的 notes 原稿，发布器验证后复制到“成果”。不靠符号链接连接两层，也不放宽 Agent 路径规则。

课程日期仅接受显式 YYYY-MM-DD 或 course_info.json 的 lectureDate/lecture_date；新版智云 userscript 会从讲次 `sub_title` / 明确 lecture-date 字段提取并写入该值。exportDate、下载时间和文件修改时间都不是日期来源。新 marker v3 记录实际 `folder_name_style`，因此既支持 `课程名称-09-17`，也支持课程专用根目录下的 `09-17`；完整年份仍保存在 marker/manifest，并继续用于内部成果文件前缀。未知日期对应 `课程名称-日期待确认` 或 date-only 模式下的 `日期待确认`。旧 marker v1/v2 工作区继续兼容，不自动迁移。旧任务确认新日期/改名不能静默重定位，需使用新讲次 ID。

旧工作区不自动迁移。显式迁移时必须同步相对图片链接、任务身份与状态，并保留历史成果。原始 ZIP 不重命名。移交成果文件夹后，正文、图片与 Complete 展开内容仍应可读；临时副本不能成为成品依赖。

发布副本保留 notes/slides 的相对关系，正文与链接字节不改；复制整个“成果”后可独立读 Markdown，本地图片按实际引用复制。HTML 仅发布与 Markdown 双哈希绑定的版本。远程图片会明确报告离线不完整。已有同名不同内容的成果拒绝覆盖；同内容发布幂等；多个模式可部分完成，缺失模式单独列 pending。原稿和历史成果均保留。

清理必须先预览范围、影响和空间，再由用户确认；只处理可重建且非活跃的确切条目。不得把唯一证据、历史成品或任务恢复记录当成缓存。

cache-status/cache-clean 接受外层课程目录；清理精确条目前核验正式工作区，并逐文件确认缓存内容已在正式资料中保留。失败准备留下的成功阶段不能当作唯一资料删除。旧工作区仍使用原缓存接口。Windows 桌面/终端真机与真实课程视觉/语义验收尚未由合成回归替代。
